# 222：反聊天、反刷人的线下偶遇机器

## 一句话判断

222 不是“又一个交朋友 App”。它更像一台城市级的线下偶遇机器：用户不刷头像、不写 profile、不 DM，只表达愿意参加，产品把他送进附近的公共场合体验，并按 curation profile 把更可能合拍的人编到同一组。

它强化的是弱关系转强关系、同城半熟人关系、线下小组关系和身份/安全边界关系。关系强度来自共同经历、稀缺邀请、小组安全感、事前筛选和低尴尬到场，而不是聊天框。

## 它强化哪一种关系

222 强化的是四层关系：

1. **弱关系转强关系**：起点是陌生人，但产品目标不是线上互关，而是把人送进一次可共同回忆的线下体验。
2. **同城半熟人关系**：附近的人本身没价值；附近、同一时间可到场、经过筛选、坐在同一张桌子的人才有价值。
3. **线下小组关系**：小组比 1v1 更安全，比大型活动更容易记住人，也更不容易变成面试或相亲。
4. **身份/安全边界关系**：vetted member、public setting、group setting 和 no DMs 都是在限制陌生社交最容易腐烂的地方。

它不是熟人维护工具。它解决的是“怎样让陌生人先安全、自然、低尴尬地变成半熟人”。

## 真实痛点

用户不缺聊天工具，也不缺约会软件。用户缺的是一个不丢脸、不像 networking、不需要自己组织、也不用刷半小时人的见面理由。

222 压缩了五个摩擦：

- **选择摩擦**：不用浏览照片、bio、prompt，也不用猜对方到底是交友、约会还是找资源。
- **邀约摩擦**：没有“先 DM，再寒暄，再试探时间”的尴尬链路。
- **组织摩擦**：地点、活动、同组人和时间由产品安排。
- **安全摩擦**：公共场合 + 小组 + 事前 vetting，是陌生人线下见面的最低安全配置。
- **身份表演摩擦**：no profiles 不是少功能，而是减少社交媒体式自我包装。

这点很锋利：222 没有承诺“帮你找到朋友”，而是承诺“给你一次更高概率不浪费的 chance encounter”。这比“我们有一个兴趣社区”具体得多。

## 关系强度靠什么增长

222 的关系增强机制不是信息流，而是现场履约：

- **共同经历**：dinner、comedy、happy hour、城市体验，比线上匹配更容易留下记忆。
- **稀缺准入**：用户不是无限刷，而是收到 invite、被选入 experience；稀缺会筛掉低意图用户。
- **小组安全感**：多人场景降低失败成本，也减少 1v1 的压力和风险。
- **事前筛选**：curation profile 和 member vetting 把“谁可以坐到一桌”变成产品判断。
- **重复到场**：如果前两三次体验都不错，222 就可能从 novelty app 变成城市生活入口。
- **低尴尬约束**：no DMs / no swiping 砍掉了陌生社交里最耗、最脏、最容易 dating 化的环节。

这是真关系机制，不是伪社交壳。它改变了关系发生方式：先共同经历，再决定要不要继续联系。

## 冷启动与网络效应

222 的冷启动是 **个人需求入口 + 城市体验供给 + 小组匹配**：

1. 单个用户因为搬城、孤独、想探索城市、厌倦刷屏而下载。
2. 用户完成 curation profile，表达愿意参加 nearby social experiences。
3. 产品挑选公共场景和同组人，用户只需说 yes 并到场；官网当前写的是 5-7 个 compatible matches，而不是无限大群。
4. 好体验形成故事：“这个 app 不让你聊天，直接把你送去和几个人见面。”
5. 城市密度起来后，匹配池、体验供给和口碑一起变好。

它有真实网络效应，但边界很窄：

- **真实部分**：同城用户越多，匹配越能细分；体验供给越多，越能安排合适的场景。
- **局部部分**：网络效应主要是城市级。洛杉矶体验好，不代表上海、杭州自然成立。
- **脆弱部分**：如果 vetting 和匹配质量跟不上，用户越多反而越杂，会滑向低质量陌生人局。
- **关键判断**：护城河不在 App 壳，而在匹配质量、城市运营、安全机制和复购仪式。

## AI-native wedge

222 目前没有把自己明确包装成 AI-native 产品。它值得学的是“关系判断层”，不是聊天 UI。

如果迁移成 AI 关系助手，最小 wedge 应该是：

- **用户给什么**：城市、今晚/本周可用时间、预算、活动偏好、年龄段、职业/学校、兴趣、社交能量、禁忌边界、本次关系目标、可公开名片和安全限制。
- **系统 30 秒内返回什么**：一个可执行的小组体验，包含主题、地点类型、人数结构、为什么这几类人适合坐一起、参与者轻量可信卡、低尴尬破冰问题、活动后 follow-up 建议。

AI 的价值不是生成油腻邀约话术，而是压缩“选人、组局、破冰、安全边界、后续关系沉淀”的判断成本。

## 迁移到旦聚旦时，Q&A 应该怎样变成小组匹配

222 的启发不是“问一堆兴趣题，然后让 AI 随机凑桌”。强关系匹配必须把回答落到明确的 profile 维度，再影响谁能坐到一桌、谁不能坐到一桌、谁需要人工审核。

### 三层问题

1. **必须信息**：复旦身份验证、所在城市、可参加时间、职业/行业、当前关系目标、是否接受和陌生校友线下见面、可公开名片范围、硬性安全边界。
2. **补充信息**：本周想解决的问题、愿意提供的帮助、想认识的人、社交能量、预算、场地偏好、是否接受混龄/跨行业/跨校区组合。
3. **高级偏好**：是否接受被介绍给投资人/创业者/求职者/租房同伴，是否接受活动后互换联系方式，是否愿意担任下一桌 co-host。

### answer → profile score → matching strategy

| 维度 | 由哪些回答改变 | 匹配怎么变 |
| --- | --- | --- |
| 身份可信度 | 校友认证、职业名片、共同联系人、过往到场记录 | 低分只能进公开主题局；高分可进更私密的 founder dinner、求职互助、租房避坑局。 |
| 关系开放度 | 是否接受新朋友、是否愿意后续联系、是否接受被介绍 | 开放度高的人适合做连接节点；低的人更适合主题明确的小范围讨论。 |
| 互助供给度 | 能提供经验、人脉、岗位、房源、中介评价、创业资源 | 每桌至少放 1-2 个供给者，避免全是索取方。 |
| 需求急迫度 | 求职、融资、找合伙人、搬家租房、刚到新城市 | 高急迫度需要更强主题匹配和活动后 follow-up，而不是泛兴趣局。 |
| 社交风险敏感度 | 性别安全、酒精边界、夜间出行、陌生人接受度 | 决定场地、人数、是否需要主理人在场、是否只开放校友实名局。 |
| 主题匹配度 | AI 创业、职业转型、上海新校友、租房互助、行业方向 | 决定桌子的主题，不让“都很优秀”这种空理由糊弄用户。 |
| 复联价值 | 活动后互评、想继续聊的人、可帮到谁 | 决定下一次组局和一对一介绍，不把关系停在一次饭局。 |

### 输出不该是“推荐用户”，而该是“这一桌为什么成立”

旦聚旦的 30 秒输出应该长这样：

- **给主理人**：本周建议开 2 桌：上海 AI 创业校友桌、亦庄租房避坑桌；每桌 5-6 人；谁必须审核；谁适合做暖场节点；哪些人不能放一桌。
- **给参与者**：你被邀请是因为你的当前目标、可提供帮助和这桌主题匹配；公开显示哪些名片字段；到场前知道什么边界。
- **给系统**：活动后收集互评、继续联系意愿、实际帮助发生情况，更新下一次匹配，而不是只统计报名数。

这才是 AI-native wedge：用户不是来填问卷的，用户是来把“我该见谁、为什么见、见完怎么继续”交给一个可信的关系判断层。

## 为什么用户会来、留、传播、付钱

### 为什么会来

用户来是因为他们厌倦了刷人、滑卡、尬聊和 networking 酒会，也不想自己拉群组局。222 给了一个具体承诺：不用表演自己，去一个公共场合，见一组更可能合拍的人。

### 为什么会留

留存取决于第一次是否不尴尬、第二次是否明显更准。如果用户连续两三次都遇到“值得再见的人”，222 就会从新鲜玩具变成城市社交入口。

### 为什么会传播

传播单元是故事，不是邀请码：

- “这个 App 不让你聊天，直接把你送去和匹配的人见面。”
- “我本来以为会尴尬，结果那桌人还挺准。”
- “下次我们一起试试？”

这种故事适合 TikTok、Instagram、小红书，也适合朋友间口碑传播。反社交媒体、反 dating、反 networking 的姿态足够鲜明。

### 谁为什么付钱

最直接付费方是用户本人：为被筛选、被组织、低尴尬的线下体验付费。

潜在付费方还包括：

- 餐厅、酒吧、comedy club、展览和城市体验商家：为高质量客流和填座付费或分成。
- 企业、学校、relocation 服务：为新员工、新生、校友城市融入购买体验。
- 城市主理人：作为供给侧合作者拿分成，但不能让体验变成廉价活动票务。

广告不适合作为主线。强关系产品一旦让用户觉得自己被卖给商家，信任会塌。

## 事实、判断、可复制机会、风险

### 事实

- 222 官方首页定位围绕 meet new people、discover your city、deepen relationships 和 chance social encounters。
- App Store 描述强调 no profiles、no DMs、no scrolling、no swiping。
- Apple API 描述写明 222 sends invites to social experiences happening nearby；体验在 public 和 group setting 中发生；member 会在被选入体验前 vetted。
- iOS App 免费下载，官方公开描述没有足够信息确认体验收费、退款、场地方分成或会员机制。

### 判断

222 最强的判断是“反聊天”。很多社交产品默认多给用户一个沟通通道，但强关系真正难的是见面的理由、可信的筛选和低尴尬的共同经历。

它的最大风险也在这里：用户把组织权交给产品，产品就必须对每一次到场体验负责。匹配差、场地差、安全感差，都会被归因给 222。

### 可复制机会

- **校友小桌匹配**：不要泛陌生人，先用学校、城市、行业、人生阶段和实名名片建立信任边界。
- **AI 组局工作流**：输入目标和候选人，输出 4-6 人结构、活动页、邀约文案、破冰问题和复盘。
- **公共场合 + 小组 + vetting**：这是中国迁移的底线，不是锦上添花。
- **活动后关系资产**：谁值得继续约、谁适合介绍给谁、下一局缺什么角色，比活动报名表更有长期价值。
- **反私信设计**：不要急着做无限私信。先让关系在可信场景发生，再开放后续连接。

### 风险

- 线下陌生人见面天然涉及骚扰、欺诈、酒精、投诉、女性安全和责任边界。
- 城市运营重：每个城市都要有用户密度、场地合作、客服、退款和活动节奏。
- 很容易 dating 化；即使产品说不是 dating，用户动机会把它往 dating 拉。
- 如果体验本身不强，222 会退化成随机活动票务，网络效应就很弱。
- 中国迁移的监管和安全压力更大，泛陌生人方向不该作为第一站。

## 对旦聚旦与巢聚的启发

### 对旦聚旦

旦聚旦最该学 222 的不是“陌生人见面”，而是 **curation profile + 小桌体验 + 活动后关系沉淀**。

最小版本：

- 复旦校友填写身份、城市、行业、当前目标、可公开名片和边界。
- 系统每周发一个小桌邀请：AI 创业、求职转型、创始人互助、上海新校友、租房互助。
- 不做广场，不做无限私信；先做 vetted alumni 的小组见面。
- 活动后生成共同记忆卡、值得 follow-up 的人、下次组局建议。

这能弱化主理人依赖。主理人不需要每次手工想主题、拉人、写文案，系统先给出“这桌为什么成立”。

### 对巢聚 / 租房

222 对巢聚的启发不是“做租房社交”，而是把租房信任变成小组互证场景：

- 同校、同公司、同园区租客小桌；
- 北京亦庄新员工通勤与合租匹配；
- 可信中介答疑局；
- 黑中介 / 假房源风险共识卡。

巢聚如果只做房源列表，是红海。更小的楔子是：把有共同身份的人带到一个可信场景里，让他们互相验证中介、房源、通勤和预算，再沉淀可信名片和避坑记录。

## 下一步最该查

1. 222 的体验是否收费？价格、退款和场地方分成公开信息不足。
2. 它的 vetting 是人工审核、身份验证、社交图谱，还是行为数据风控？
3. 它在哪些城市密度最高，是否集中在 LA / NYC / Chicago / San Francisco / Toronto / DC / London / Orange County？
4. 第一次 experience 到第二次 experience 的复购率有没有公开数据？
5. 对旦聚旦，第一版该不该先做“校友 5 人小桌”而不是完整社交 App？我的判断：应该，而且先半自动人工审核，别急着全自动匹配。
