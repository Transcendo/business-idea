# BitBoard

## 一句话判断

BitBoard 值得跟踪：它不是做“医疗 AI 助手”这种泛题目，而是直接切医疗 back-office，把 intake、chart prep、referral 这类高重复、可 SOP 化的行政任务交给 agent 执行。这个方向的创业价值在于，它对应的是明确的付费方、明确的流程和明确的 ROI。

## 这家公司在做什么

BitBoard 的官方页面把自己描述成“build dashboards and reports with AI”，但在 healthcare launch 里，它更清楚地展示了核心方向：为诊所和医疗集团提供能按 SOP 执行的 AI agents，去处理重复的后台行政工作。

它在 HN launch 里举的典型场景包括：

- 根据 records 预先整理 patient chart；
- 填 intake form；
- 处理 referrals；
- 把 clinic SOP 转成可执行的 agent workflow；
- 在 EHR 和内部工具里做后台操作。

它强调的不是“更聪明的聊天”，而是：

- 让 clinic 直接把 SOP 交给系统；
- 用 verification / deterministic checks 保证执行结果可审计；
- 以 task-based 方式收费；
- 通过 HIPAA compliance、audit log 和 zero-retention 来降低采购阻力。

## 为什么值得关注

1. **切口很具体。** 医疗机构最贵的不是宏大 AI 叙事，而是把人从重复行政里解放出来。intake、referral、chart prep 这些活都是真实成本。

2. **买单方清楚。** 诊所、医疗集团、运营团队都能直接感受到节省的人力和缩短的等待时间。

3. **SOP 化是好信号。** 能被写成 SOP 的工作，才更适合 agent 化；这比“做一个通用医疗助手”更容易落地。

4. **它踩在更大趋势上。** 医疗 AI 正在从“生成内容”转向“执行工作流”。BitBoard 代表的是 agent 进入 EHR / clinic ops 的第二阶段。

## 风险与观察点

1. **EHR 和内部工具太碎。** 医疗后台系统不统一，自动化很容易被界面变化打断。

2. **验证成本高。** 医疗场景里不能只看能不能做完，还要看做得对不对。

3. **销售周期不短。** 即便 ROI 明确，医疗机构采购和安全审查依然慢。

4. **平台化要谨慎。** 先把少数高频任务做深，比一开始讲“全栈 agent 平台”更重要。

## 我们的判断

BitBoard 是一个很值得持续盯的 AI 医疗方向：医疗后台行政自动化 + 可验证 agent 执行层。它的意义不只是“省人”，而是把医疗机构里原本靠 contractor 和人工协调完成的工作，变成可复用、可审计、可扩展的基础设施。

后续重点看三件事：
- 是否能在真实诊所里稳定跑通；
- verification 机制能否把错误率压到足够低；
- 是否从单点任务扩展到更广的 healthcare ops workflow。
