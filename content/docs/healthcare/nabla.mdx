# Nabla

## 一句话判断

Nabla 值得看，因为它把 ambient clinical documentation 从“医生少打字”推进到 EHR 内的文书、编码提示和临床工作流入口；这条线如果走通，它抢的是医生每天最频繁接触的医疗软件入口。

## 为什么推荐

1. **它切的是医疗里真实、昂贵、长期存在的摩擦。** 临床文书同时影响医生时间、患者沟通、编码计费、质量审查和责任追溯。这个需求不靠 AI 热度也存在，AI 只是让产品形态突然可用。
2. **公开采用信号已经够强。** Nabla 官网显示，其已部署在 150+ health organizations，被 85,000+ clinicians 使用，每年覆盖 20M+ patient encounters。医疗采购慢、集成重、医生使用门槛高，这组数字至少说明它不是 demo 产品。
3. **它不是只做 scribe。** Nabla 的 EHR 页面强调 multi-EHR integration、Nabla Connect、结构化 notes、ICD-10 / HCC / MCC coding suggestions 和 documentation nudges。重点在于：它想从生成病历，扩到 EHR 内的实时临床文档操作层。
4. **临床证据开始变硬。** Nabla 官方 press release 引用 NEJM AI 随机临床试验：238 名医生、14 个专科、48,000+ outpatient visits；Nabla 组 time-in-note 相比 control 下降 9.5%，并称其为试验中唯一在 primary efficiency outcome 上达到统计显著改善的 intervention group。

## 产品 / 项目解析

Nabla 最容易被误读成“法国版 Abridge”或“又一个 AI 医疗书记员”。这个判断太粗。

Ambient scribe 的第一层价值是让医生少打字。但真正的大机会不在 note 本身，而在 note 生成时同时发生的三件事：

- 医生和患者交流被结构化成 EHR 可用的数据；
- 编码、风险调整、质控要求可以更早被提示；
- 医院可以把分散的临床文档动作，变成更一致、更可审计的流程。

Nabla 的产品叙事正朝这个方向走。它不是只强调“录音转文字”，而是把 ambient AI、dictation、自定义 note 格式、多语言、EHR 嵌入、coding suggestions 和 documentation nudges 放在一起讲。

这里有一个关键点：医生不想再打开一个新系统。医疗 AI 如果不能贴进 Epic、athenahealth 或其他 EHR 的日常流程，再聪明也很难成为默认工具。Nabla Connect 的价值就在这里：如果它真能让 EHR 厂商或 health system 以较轻的方式嵌入 ambient AI，它的分发路径会比纯 SaaS 销售更顺。

我对 Nabla 的判断是：它不一定比 Abridge 更“平台级”，但它在产品轻量化、跨 EHR 适配和临床端体验上有清晰打法。这个市场最后未必只有一个赢家，因为不同 health system 对证据、集成、价格、医生偏好和平台依赖的权重不同。

## 投资人视角的批判与风险

1. **赛道已经很挤。** Abridge、Microsoft Nuance DAX、Suki、Nabla 都在争同一块核心预算。Nabla 需要证明自己不是一个体验更好的替代品，而是能长期占住工作流入口的公司。
2. **平台方压力很真实。** Epic、Oracle Health、Microsoft/Nuance 都有动机把文书 AI 变成原生功能。独立公司的优势是速度和专注，劣势是分发与系统控制权。
3. **官网指标需要拆开看。** 150+ organizations、85,000+ clinicians、20M+ annual encounters 是强信号，但还不能替代 ARR、净收入留存、活跃使用率、部署深度和续约率。
4. **官方页面存在口径更新时间差。** 首页显示 150+ health organizations，EHR 页面仍写 130+ orgs。大概率是页面更新不同步，但这提醒我们：采用数据要谨慎引用，最好持续追踪客户名单和正式 case study。
5. **医疗责任和隐私风险不会消失。** HIPAA、GDPR、SOC 2 Type II、ISO 27001 是入场券，不是护城河。文书遗漏、错误编码、hallucination、患者 consent 和审计责任，都会在真实部署里被放大。

## 可借鉴点

- 在重监管行业，先做高频、痛苦、可审计的 workflow，比一上来替代专业判断更聪明。
- 医疗 AI 的商业化不应只讲“节省时间”，还要尽快连接收入、合规、质控和运营指标。
- 跨 EHR 集成可能是独立公司的战略位置：不绑定单一平台，反而能服务多系统医院。
- 从 note generation 到 coding suggestion，再到 documentation nudge，是一个自然扩展路线。

## 后续跟踪点

- 是否披露更具体的 enterprise revenue、续约率、部署深度与活跃 clinician 数据
- Nabla Connect 是否能成为 EHR 厂商侧的默认嵌入方案，而不是销售页上的集成叙事
- coding suggestions 和 documentation nudges 能否转化为客户愿意付费的财务收益
- 面对 Abridge 与 Microsoft/Nuance，Nabla 的差异到底来自产品体验、价格、部署速度还是临床证据
- 医疗机构是否把 Nabla 视为单点 scribe 工具，还是愿意让它进入更核心的 clinical documentation governance
