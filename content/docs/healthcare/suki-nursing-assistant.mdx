# Suki Nursing Assistant

## 一句话判断

Suki 的 Nursing Assistant 不是“又一个医疗 AI 助手”。更准确地说，它在把 ambient clinical AI 从医生文书推进到护士工作流：评估表、admission forms、discharge documentation、flowsheets、handoff 和 EHR 内碎片操作。

这个方向值得看，因为护士不是缺聊天框，而是被记录、表单、交接和系统切换拖住。AI 如果能把床边观察、语音、上下文和 EHR 字段压成可确认的护理记录，就能碰到医院真实预算。

## 赛道 / 产品信号

- Suki 官方宣布成立 nursing consortium，成员包括 health systems、rural providers 和 care teams，目标是把一线护士反馈纳入产品设计。
- Healthcare IT News 报道称，Suki 推出面向护士的 AI assistant，并聚焦 EHR 内 forms、flowsheets 和常见护理文档。
- Suki 还和 AvaSure 这类 virtual care / smart room 方向公司合作，说明它不只想做独立听写工具，而是往病房工作流入口靠。
- 医生 ambient scribe 已经很挤。护士工作流还没被充分产品化，但护理短缺、行政负担、EHR 摩擦都更硬。

## 用户痛点是什么

护士的痛点不是“不会写记录”。痛点是：

1. **工作被切碎。** 床边观察、病人沟通、医嘱执行、监测、交接、家属沟通和 EHR 填写不断打断。
2. **表单和 flowsheet 高频重复。** 很多字段不是创造性工作，却必须准确、及时、合规。
3. **交接风险高。** 护理信息丢失不是小问题，会影响用药、跌倒风险、出院安排和责任追踪。
4. **EHR 不是为护士节奏设计的。** 点选、查找、复制、补录会挤占床边时间。
5. **医院买的是运营结果。** 减少加班、减少遗漏、缩短 documentation time，比“AI 很聪明”更能进预算。

## AI-native wedge

更好的 wedge 不是“护士聊天机器人”，而是：

**护士说出或录入一次病人状态；系统自动生成结构化护理记录、待确认 flowsheet 字段和交接摘要。**

最小可用版本：

- 语音 / 文本捕捉床边观察。
- 自动映射到对应 EHR 字段。
- 标出不确定字段，让护士点选确认。
- 生成 handoff note 和风险提醒。
- 所有自动填充都留审计轨迹。

这才是 AI 在压缩任务：把“观察 → 回忆 → 找字段 → 填表 → 交接”压成“说一次 → 确认差异”。

## 为什么现在

- 医生 ambient documentation 已经教育了医院市场，采购方知道这类产品能落在 EHR 工作流里。
- 护理短缺长期存在。医院不能靠多招人解决所有记录负担。
- 病房硬件、virtual nursing、remote observation、smart room 正在给护理 AI 提供更多输入源。
- EHR 集成能力比前几年成熟。AI assistant 不必永远停在旁路笔记。
- 生成式 AI 的价值从“生成文本”转向“填对结构化系统”。护理正好是结构化系统摩擦重灾区。

## 用户为什么来 / 留 / 传播 / 付费

**为什么来：**
护理管理层会被两个指标拉进来：documentation time 和 nurse burnout。护士本人会被“少补录、少加班、少漏交接”吸引。

**为什么留：**
只要系统能稳定写进 EHR，留存来自日常工作依赖。护士每班都要记录，医院每班都要交接。

**为什么传播：**
传播物不是产品官网，而是前后对比：一次入院评估从 12 分钟压到 4 分钟，交接摘要自动带出跌倒风险、导管状态、用药变化。这类案例会在护理管理者、CNO、临床信息化团队之间传播。

**谁付费：**
health system、医院集团、virtual nursing 服务商、EHR 生态合作伙伴。付费理由是护理效率、记录完整率、合规审计、减少加班和降低交接风险。

## MVP 实验

### 7 天 MVP

别一开始接完整 EHR。先做一个窄场景：**admission nursing assessment copilot**。

输入：护士口述或粘贴一段入院观察。

输出：

- 结构化 assessment 草稿。
- 需要护士确认的字段。
- handoff summary。
- missing info checklist。

只支持 3 类常见护理场景：入院评估、跌倒风险评估、出院教育。

### 30 天验证

找 5-10 名护士或护理信息化人员做模拟病例测试。

验证问题：

- 草稿是否减少补录时间。
- 字段映射是否可信。
- 护士愿不愿意确认，而不是重新写。
- 哪些字段必须保持人工输入。
- 哪些输出能进入交接，而不是只适合演示。

## 可验证指标

- 单份 admission assessment 平均完成时间。
- AI 生成字段的一次通过率。
- 护士手动修改比例。
- missing fields 减少比例。
- handoff note 被实际采用比例。
- EHR 内点击次数减少量。
- 每班结束后补录时间减少量。

## 商业化路径

1. **护理文档模块。** 按护士 seat 或医院科室收费。
2. **virtual nursing bundle。** 和远程观察、smart room、病房摄像 / 音频工作流结合。
3. **EHR marketplace。** 通过 Epic / Oracle Health 生态做轻量分发，但不能只靠 marketplace。
4. **护理运营控制台。** 给护理管理层看漏项、交接质量、文档延迟和高风险病人流转。

## 反例 / 风险

1. **护士工作流比医生文书更碎。** 如果产品不能适配不同科室，很容易变成 demo。
2. **EHR 写入很难。** 旁路摘要有用，但预算更强的地方在系统内字段。集成做不深，价值会打折。
3. **错误成本高。** 护理记录涉及病人安全和责任追踪。AI 必须让护士确认，不能黑箱自动写入。
4. **护士不一定愿意被“监控”。** 如果产品被理解成管理层监控劳动强度，会遭遇抵触。
5. **大厂和 EHR 会下场。** Suki 的机会在护理场景深度、临床体验和跨系统协作，不在单纯语音转文字。

## 后续跟踪点

- Suki for Nurses 是否能从 forms / flowsheets 扩到交接、discharge planning 和 virtual nursing。
- 医院是否公开披露 documentation time、nurse satisfaction、EHR clicks 等结果。
- AvaSure 合作是否变成真实病房部署，而不是联合营销。
- 护理 AI 的最佳入口到底是 ambient voice、smart room、virtual nurse，还是 EHR 内 copilot。
