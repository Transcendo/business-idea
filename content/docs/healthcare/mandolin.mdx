# Mandolin

Mandolin 值得跟，不只是因为它在讲 agentic AI，而是因为它切进了 **specialty drug access** 这条真钱流、重流程、强嵌入的赛道。

我更关心的不是它会不会“自动做表单”，而是它是否正在把 **输注中心、专科药房与 health system 后台** 那层最琐碎、最缺人、但又最直接影响患者开药速度与机构现金流的工作，变成一个可扩张的软件层。

## 为什么值得看

我今天选 Mandolin，核心有四点：

1. **买单方明确**，不是泛医疗创新预算，而是 infusion center、specialty pharmacy、health system 的运营与收入相关预算。
2. **流程足够刚需**，从 intake、benefits verification、prior auth 到 claims statusing 和 appeals，本来就是每天都必须做的活。
3. **价值不只在提效**，它直接影响 time-to-treatment、denial rate、回款周期和人力配置。
4. **有初步落地信号**，官方已公开 700+ clinical locations、25 万+ annual new patients、以及 document processing、Rx backlog、外包 FTE 调整等量化结果。

这条线真正有意思的地方在于，它不是在做“医生更爱用的 AI 工具”，而是在做 **让高值 specialty 药物流转得更快、回款更稳的后台操作系统**。

## 产品 / 项目解析

Mandolin 的产品逻辑很清楚，它不是单点 prior auth 工具，也不只是 OCR。

它想吃掉的是 specialty drug access 的整条行政链路：
- referral intake 与 onboarding
- benefits verification
- patient out-of-pocket estimation
- medical policy review 与 prior authorization
- claims statusing
- appeals automation

官方公开信息里最值得注意的一点，是它强调自己的 AI agents 不是只做“理解”，而是会 **reason、click、call、follow up**，也就是直接在 payer portal、EHR、manufacturer hub、传真和电话之间推进任务。

这意味着它瞄准的不是一个小 widget，而是 healthcare back office 里最难平台化的那部分“跨系统人工劳动”。

## 为什么这条创业方向值得持续看

### 1. 它卡在 specialty 药这个高价值环节

specialty 药本身金额高、审批复杂、流程长。谁能把这一层的行政摩擦降下来，谁就不只是提效，而是在影响患者起始治疗时间和机构收入实现速度。

### 2. 它天然连接 payer 规则与 provider 运营

这类公司如果做深，既理解 payer policy，也理解 provider 的 buy-and-bill、药房运营和患者费用测算。这个位置很容易长出更厚的工作流壁垒。

### 3. 它比很多“医疗 AI 助手”更接近真实预算

很多医疗 AI 产品最后卡在“有人喜欢，但预算不稳定”。Mandolin 这类方向更接近 revenue-adjacent software，只要能压缩授权时长、减少拒付、降低外包和人工成本，预算理由就更硬。

### 4. 它踩在监管顺风上

CMS-0057-F 已经在推动 prior authorization 时效与 API 能力建设。监管是在逼行业把这套旧流程电子化、可解释化、可追踪化。对这类自动化平台来说，这不是噪音，而是顺风。

## 投资人视角的批判与风险

### 风险 1，交付复杂度可能很高

虽然官方写着 "No APIs. No integrations."，但真正进入不同 payer portal、EHR、电话系统与药房流程，背后仍然可能是很重的适配工作。

### 风险 2，流程自动化容易被巨头包围

specialty 药 access 周围本来就有 PBM、hub service、RCM、prior auth vendor 和 specialty workflow 平台。Mandolin 能否站住，不只取决于模型能力，还取决于切入点和速度。

### 风险 3，AI agent 的可靠性必须长期被验证

它越往 claims、appeals、patient cost estimation 这类高后果流程走，市场越不会只听“自动化很强”，而会看 traceability、auditability 和 exception handling。

## 我的判断

如果说 Latent 更像从 payer 侧和药物准入规则切入，Mandolin 更像从 **provider / pharmacy 侧的 specialty drug back office** 切入。

我会持续跟这条线，因为它体现了一种我很看重的 AI 医疗创业方向：

**不是做一个更聪明的前台助手，而是把治疗开始前那一整层高摩擦、强合规、强收入关联的人工流程，做成真正可扩张的运营基础设施。**

## 后续跟踪点

1. **真实 time-to-treatment 改善是否能持续公开**，尤其是在不同病种、不同 payer mix 下是否依然成立。
2. **它会不会从行政自动化继续往 specialty access system of record 走**，而不只是做自动执行层。
3. **和 SamaCare、payer prior auth 工具、hub 服务的边界会怎么演化**，这是判断天花板的关键。
4. **监管 API 与现有 fax / portal 现实之间，它到底是在吃过渡红利，还是会成为长期基础设施。**
