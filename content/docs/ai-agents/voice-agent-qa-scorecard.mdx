# Voice Agent QA Scorecard

## 一句话判断

语音 agent 真正进入生产后，下一层机会不是再做一个接电话 demo，而是把延迟、打断、听错、转人工和业务写入压成可复测的 QA scorecard。

电话任务比网页 agent 更残酷。网页慢一点还能等，电话里 1 秒沉默、一次抢话失败、一个地址听错，用户就开始不信它。企业买语音 agent，最后不是买“声音像真人”，而是买一套能证明它每周稳定完成任务的证据系统。

## 赛道 / 产品信号

本轮看到几类信号叠在一起：

- Product Hunt 上 Vapi 的产品页直接把卖点写成 “Build, test and deploy voicebots in minutes rather than months”，评论问题里出现 call latency 是否低于 500ms、barge-in 是否处理自然、voice quality 是否稳定这些 QA 维度。
- Vapi 官方文档目录里有 Testing、Scorecard、Monitoring、Debugging voice agents、IVR navigation、Handoff tool 等模块。说明生产语音 agent 的核心工作已经从“能说话”转向“能被测试和运营”。
- LiveKit Agents 官方文档把自己定位成 realtime framework for voice, video, and physical AI agents，并提供 testing / evaluation、turn detection / interruptions、agents & handoffs 等页面。
- AG2 的 LiveAgent 博客展示 GPT Realtime 2 / Gemini live audio 接入，强调 VAD、turn detection 和 interruption。
- deepsense.ai 的企业语音 AI 文章直接把问题落在 latency、native audio model、voice-to-voice pipeline 和企业部署上。
- HN 近期有低延迟 voice agents、macOS 电话式 coding agent、地产 voice agent、企业实时语音模型测试等小信号。单条不炸，但方向密度变高。

判断：语音 agent 的第一波机会是 runtime；第二波更像 QA / eval / monitoring 层。谁能让业务负责人放心放量，谁才离预算更近。

## 用户痛点是什么

语音 agent 的采购方最怕这些事：

1. **延迟不可控。** 平均延迟漂亮没用，P95 卡住就会毁掉真实通话。
2. **打断处理差。** 用户会插话、改口、纠正、沉默。agent 如果只按文本轮次走，会像客服脚本机。
3. **关键信息听错。** 时间、地址、姓名、金额、订单号、邮箱，一错就是业务事故。
4. **转人工没有证据。** 转过去只给一句“用户需要人工”，真人还得重新问。
5. **业务写入难验收。** CRM、日历、工单、支付前确认是否写对，需要可查记录。
6. **上线后缺回归测试。** 改 prompt、换模型、换 TTS 后，旧场景可能悄悄变差。

真实痛点不是“没有语音 agent”。真实痛点是：企业不敢把真实电话流量交给一个黑箱。

## AI-native wedge

最小 wedge：

**用户上传 20 条历史通话、业务话术和目标字段；系统自动生成一组语音 agent 回归测试，并输出每个版本的 latency / barge-in / extraction / handoff / write-back scorecard。**

这不是传统质检报表。AI 压缩的是从听录音、标注失败、改 prompt、回放测试、对比版本到决定是否放量的整段 QA 工作。

第一版可以只做三件事：

- 把真实通话转成测试场景：用户插话、环境噪声、字段纠错、沉默、敏感问题、转人工。
- 对每次 agent 运行打分：首响延迟、P95 延迟、打断恢复、字段抽取、任务完成、合规话术、转人工摘要。
- 生成 release gate：这个版本能不能放到 5%、20%、100% 电话流量。

## 为什么现在

- Realtime audio model 和 LiveKit / Vapi / AG2 这类工具降低了搭建 voice agent 的门槛，更多团队会从 demo 走向生产。
- 生产后最先暴露的不是模型是否聪明，而是延迟、打断、质检、回归测试和转人工。
- Product Hunt 的 Vapi 页面已经把 latency、barge-in、voice quality 放进用户评价问题里，说明市场开始用生产指标而不是 demo 新鲜感衡量产品。
- 企业客服、房产、招聘、诊所、本地服务都有高频语音任务，但这些行业不可能无证据地把电话流量全交给 agent。
- 文本 agent 已经出现 eval、observability、prompt regression；语音 agent 会复制这条基础设施曲线，只是指标更硬。

## 用户为什么来 / 留 / 传播 / 付费

**为什么来：**

团队已经有 voice agent demo，但上线前没人敢拍板。老板问“会不会听错、会不会卡、会不会乱转人工”，工程和运营拿不出证据。

**为什么留：**

每次改 prompt、模型、声音、工具集成都要跑回归测试。只要系统变成 release gate，它会嵌进上线流程。

**为什么传播：**

可传播单元是放量报告，不是炫技视频：

```txt
Voice Agent v18 放量建议：20% → 60%
首响 P95：720ms
打断恢复：91%
预算字段准确率：96%
转人工摘要完整度：88%
高风险话术：0
```

这种卡会在客服、销售运营、产品和合规团队之间转发。

**谁付费：**

Voice-agent 平台、客服 BPO、保险 / 房产 / 医疗 / 教育 / 招聘等垂直语音 agent 团队，以及已经在用 Vapi、LiveKit、Twilio、OpenAI Realtime API 的企业工程团队。付费点是测试分钟数、场景库、CI gate、监控、合规规则、人工抽检席位和行业模板。

## MVP 实验

### 7 天 MVP

只做“房产中介线索初筛 voice agent”的 QA。

输入：

- 20 条脱敏历史通话 transcript。
- 一份业务字段表：预算、区域、入住时间、通勤、宠物、看房时间。
- 一个待测试 voice agent endpoint。
- 5 个转人工规则。

输出：

- 30 个自动生成测试场景。
- 每个场景的通话模拟和 transcript。
- 延迟、打断、字段抽取、工具写入、转人工摘要评分。
- 一张 release gate 卡：不建议上线、灰度、可放量。

第一版不需要做完整语音平台，只要能测试现有 agent。

### 30 天验证

- 找 5 个已经做 voice agent demo 的团队。
- 每队接入 50 条历史通话场景。
- 对比人工 QA 与自动 QA 的失败发现率。
- 看团队是否愿意在每次发版前跑一次测试。
- 记录自动 QA 找出的高风险问题是否真的阻止了线上事故。

## 可验证指标

- 从历史通话生成测试场景的可用率。
- 自动评分与人工质检一致率。
- P50 / P95 首响延迟和整轮延迟。
- barge-in 后恢复成功率。
- 关键信息抽取准确率。
- 转人工摘要完整度。
- 工具写入成功率。
- 每次发版前是否主动运行 QA。
- QA 报告是否被运营或合规负责人转发。

## 商业化路径

1. **测试场景生成。** 按历史通话条数和生成场景数收费。
2. **回归测试运行。** 按测试分钟数、并发和模型成本收费。
3. **Release gate。** 接入 CI/CD、后台发布流程、灰度开关。
4. **监控和抽检。** 上线后持续抽样，自动挑高风险通话给人工。
5. **行业模板。** 房产、诊所、招聘、保险、教育、本地服务各有字段和风险规则。
6. **平台合作。** 给 Vapi / LiveKit / Twilio / OpenAI Realtime API 用户做独立 QA 层。

## 反例 / 风险

1. **平台内置会吞基础 QA。** Vapi、LiveKit、Twilio 这类平台可以自己做 monitoring 和 scorecard。创业公司必须做跨平台、行业场景、合规证据，不能只做普通 dashboard。
2. **真实录音难拿。** 企业通话里有隐私和合规问题，MVP 必须支持脱敏、本地处理或只上传 transcript。
3. **自动评分可能骗自己。** 如果 eval 只靠 LLM 打分，会出现“看起来合理但错得稳定”。关键字段要用规则、人工抽检和业务系统结果校准。
4. **语音合成测试不等于真实用户。** 模拟器能覆盖回归，但不能完全替代线上噪声、口音、情绪和临场变化。
5. **垂直知识门槛高。** 通用 QA 只能看延迟和打断；真正值钱的是行业字段、红线话术、转人工规则。

## 创业判断

这个方向不适合做成“语音 agent 监控大屏”。那太浅，平台很快补上。

更好的切口是“语音 agent 发版前的回归测试 + 放量 scorecard”。它站在生产门口，回答一个具体问题：这个版本能不能接真实电话？

如果能把一次 voice agent 发版从人工听几十通录音压成自动场景生成、回放、评分和放量建议，客户会付费。因为它减少的不是客服成本，而是上线事故和负责人焦虑。

## 后续跟踪点

- Vapi / LiveKit 是否会把 scorecard 和 testing 做到足够强，挤压第三方空间。
- 是否存在“跨平台 voice agent QA”的采购需求，而不是只在单一平台内看报表。
- 哪个垂直行业最愿意提供历史通话做回归测试：房产、诊所、招聘、保险还是本地服务。
- 自动生成测试场景能否稳定发现真人 QA 会发现的问题。
