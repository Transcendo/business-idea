# Factory

## 一句话判断
Factory 值得看，不是因为“AI 写代码”这个题材还热，而是因为它在往一个更难、也更值钱的位置走：让大企业把软件工程里的长周期工作，逐步交给可治理、可切换模型、可嵌入现有流程的 agent 系统。

## 为什么推荐
1. **它不是做给独立开发者爽一下的工具，而是在碰真正复杂的企业工程组织。** 官方和公开报道里出现的客户包括 Nvidia、Adobe、EY、Palo Alto Networks、Morgan Stanley、Adyen，这种客户画像说明它卖的不是玩具，而是要进严肃生产环境。
2. **它的产品方向不是“更会补全代码”，而是“把工程任务组织成可长期运行的 agent workflow”。** 官网在强调 Missions、Desktop、always-on agents、governance，这比单点代码生成更接近企业真正愿意持续付费的价值。
3. **多模型路由这件事，放在企业场景里比在个人开发者场景里更重要。** 一家公司内部会同时考虑性能、成本、地区合规、供应商风险和特定任务表现。Factory 如果真把“interface and vendor agnostic”做扎实，价值不只是更灵活，而是更接近企业级 control plane。
4. **它开始试图定义评估标准，而不是只消费别人的 benchmark。** Legacy-Bench 这个动作我比较看重，因为它在把注意力从现代 web stack 拉回到真实企业遗留系统，这比很多 agent 公司只秀 demo 成绩更有判断力。

## 产品 / 项目解析
从公开信息看，Factory 的核心不是再做一个 IDE 插件，而是在做一层“agent-native software development”的操作系统。

它目前的产品叙事大致有三层：
- **Droids**：不是一次性生成代码片段，而是能在真实工程环境里持续完成任务的 agent。
- **Missions**：把多步、长周期、跨上下文的工作拆成可执行的任务结构，这明显是在对准企业工程里最难自动化的部分。
- **Desktop + enterprise integrations**：说明它不满足于浏览器里的 demo，而是要进入本地系统、开发工具链和更完整的软件业务流程。

我觉得它真正有意思的地方，不在“还能不能比 Cursor 多写一点代码”，而在于它想把软件生产从“人盯着模型逐步生成”推向“人做监督，agent 并行推进多个工作单元”。

这背后的商业含义很大：
- 如果只是 code generation，最后容易卷到模型能力和 UI 体验。
- 如果能往任务编排、验证、治理、长时执行、模型路由走，产品重心就从“副驾驶”变成“工程产能层”。

另外，Factory 公布的 Legacy-Bench 也值得注意。企业真实软件世界里有大量 COBOL、Fortran、Java 7、C 这类老系统，最值钱的工程自动化不一定发生在 greenfield AI app，而更可能发生在这些没人想碰、但业务极关键的老系统改造里。愿意正面打这块，说明它想吃的是企业预算，不只是开发者流量。

## 投资人视角的批判与风险
1. **赛道拥挤，而且最强对手不只是创业公司。** Cursor、Anthropic、Cognition、GitHub Copilot 甚至未来更多基础模型厂商都会往 enterprise coding 走。Factory 必须证明自己不是“又一个会接多个模型的 coding agent”。
2. **现在的高估值，很大程度上是在提前贴现未来组织级渗透。** 150M 美元 Series C、15 亿美元估值当然说明资本看好，但也意味着后面市场会要求它拿出非常明确的扩张证据，包括部署深度、净留存、任务完成率和大客户扩容。
3. **企业工程 agent 最大的难点不是生成，而是责任边界。** 谁批准、谁回滚、谁对错误修改负责、怎么做审计、怎么管模型升级后的不确定性，这些都决定了它能不能从“好用工具”变成“默认基础设施”。
4. **多模型策略既是卖点，也是执行负担。** 模型切换听起来很好，但要真的把不同模型的能力差异、成本结构、稳定性、合规要求和工具调用行为统一抽象起来，产品复杂度非常高。
5. **它讲的是平台故事，平台故事最怕边界失控。** 一旦既做 agent、又做 orchestration、又做 desktop、又做 benchmark、又做 governance，团队如果节奏不稳，很容易产品面太宽、价值点反而变模糊。

## 后续跟踪点
- 它能否披露更具体的企业使用数据，比如 seat 扩张、任务量、部署部门数、净收入留存
- Missions 这种长周期 agent workflow，真实完成率和人工介入率到底怎么样
- 多模型路由是不是实打实带来成本和质量优势，还是更多停留在销售叙事
- 它在 legacy code、合规治理、审计回放这些企业刚需上，能否形成明显领先
- 大客户会把它当成团队效率工具，还是逐渐把它纳入正式的软件交付流程
