# Gitar

Gitar 值得看，不是因为它又做了一个“AI 写代码”工具，而是它押注了更容易变成刚需的下游环节：当 AI 让代码产量暴增后，谁来把代码安全、稳定、可追责地送进生产环境。

## 为什么推荐

1. **它切的是正在变硬的瓶颈。** 企业真正开始痛的是 review、CI、故障归因、质量门禁，这些环节比“写出来”更接近预算和生产事故。
2. **定位比很多 agent 公司更收敛。** 它盯住 code validation / quality gate，这比泛化的“企业 agent 平台”更容易形成明确 ROI。
3. **创始人与问题匹配度高。** 团队出自 Uber developer platform 体系，对 CI、平台工程和组织级开发流程的理解更有说服力。
4. **商业落点清楚。** 如果它真能减少 CI failure 排查、重复 review、人肉合并阻塞，它卖的就是工程效率、发布速度和风险成本。

## 我的判断

Gitar 值得继续跟，因为它踩中的不是“AI 会不会继续写代码”，而是更现实的问题：当 AI 让代码量暴增后，谁来接住 review、CI 和质量门禁这个更接近生产事故的环节。
